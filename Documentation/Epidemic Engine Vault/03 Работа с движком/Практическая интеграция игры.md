# Практическая интеграция игры с SDK 1.0.1

Руководство сверено с текущими `Examples/MinimalGame`, Presentation, Session и
клиентом ASCENT 0.1.19d. ASCENT показывает рабочую композицию 2D-игры, но его
карты, бой, прогрессия, локализация и консоль — код игры, а не готовые сервисы SDK.
Публичные заголовки в `11 API` сохраняют исторический снимок; сигнатуры новых
фасадов проверяйте в исходниках, указанных в конце страницы.

## Собрать и установить SDK

Нужны Windows x64, CMake 3.25+, MSVC с поддержкой C++23 и Windows SDK.
Команды ниже выполняются из корня исходников движка в PowerShell. Используйте
установленный у вас Visual Studio generator; пример соответствует VS 2026.

```powershell
$engineRoot = (Get-Location).Path
$sdk = Join-Path $engineRoot '.ai/sdk'
cmake -S . -B build/full-release -G "Visual Studio 18 2026" -A x64 `
  -DBUILD_TESTING=OFF -DEPIDEMIC_BUILD_RUNTIME=ON -DEPIDEMIC_BUILD_FRAMEWORK=ON
cmake --build build/full-release --config Release --target EpidemicSDK --parallel 2
cmake --install build/full-release --config Release --prefix $sdk
```

Проверяйте `$LASTEXITCODE` после каждой команды; при ошибке не продолжайте.
Если `build/full-release` уже занят другой конфигурацией, выберите новый каталог.
`EpidemicSDK` собирает поставляемые библиотеки, а не весь набор приложений и тестов.
Профили с `EP_AUDITOR_PROFILE` не экспортируют production SDK.

В поставку входят headers, библиотеки, CMake package и
`share/Epidemic/sdk.json` с идентификаторами исходников, сборки и хешами библиотек.
Копируйте SDK целиком. Один номер версии не гарантирует совпадение бинарников:
сохраняйте manifest вместе с поставкой. Используйте согласованные x64 toolchain,
конфигурацию и CRT; при смене SDK пересоберите клиент в отдельном build-каталоге.

## Подключить внешний клиент

Минимальный CMake для приложения:

```cmake
cmake_minimum_required(VERSION 3.25)
project(MyGame LANGUAGES CXX)
set(EPIDEMIC_REQUIRED_ABI 1)
find_package(Epidemic 1.0.1 CONFIG REQUIRED COMPONENTS Presentation Session)
add_executable(MyGame main.cpp)
target_compile_features(MyGame PRIVATE cxx_std_23)
target_link_libraries(MyGame PRIVATE
    Epidemic::EpidemicGameFrameworkPresentation
    Epidemic::EpidemicGameFrameworkSession)
```

`EPIDEMIC_REQUIRED_ABI` проверяется при конфигурации. Components проверяют наличие
Presentation/Session в поставке. Для первого запуска используйте готовый клиент:

```powershell
cmake -S Examples/MinimalGame -B build/minimal-game -A x64 "-DCMAKE_PREFIX_PATH=$sdk"
cmake --build build/minimal-game --config Release --parallel 2
& ./build/minimal-game/Release/EpidemicMinimalGame.exe --headless
& ./build/minimal-game/Release/EpidemicMinimalGame.exe --profile "$engineRoot/.ai/minimal/profile.epidemic"
& ./build/minimal-game/Release/EpidemicMinimalGame.exe --tool
```

Здесь `--headless` проверяет запуск без окна; `--profile` — запись и чтение payload;
`--tool` — один графический кадр без заставки. Обычный запуск показывает заставку
и затем тот же кадр. Это короткий smoke-клиент, а не интерактивная игра.
Эти аргументы разбирает сам пример: Host не добавляет их автоматически любому приложению.

ASCENT 0.1.19d использует прежнюю поставку 1.0.0 через `EpidemicSDK.cmake` и
`EpidemicGameIntegration.cmake`, с собственными проверками версии/ветки. Новая
поставка 1.0.1 использует `find_package` и импортированные `Epidemic::` targets.
Замена папки старого SDK новой сама по себе не мигрирует CMake игры.

## Композиция окна, рисования и игровой логики

Для 2D-клиента начните с `presentation::Host` и `presentation::Canvas`.
Host владеет оконным циклом, вводом и startup-последовательностью. Canvas даёт
рисование, отображение и захваты. Это конкретный Win32-фасад, а не универсальный
редактор сцен. Нижнеуровневые `Application`/Runtime contracts нужны при собственной
композиции; регистрировать второй lifecycle поверх Host не требуется.

Порядок владения: Host → Canvas/игровой объект → `Host::Run(events, tick)`.
Объявите Host раньше объектов, которые на него ссылаются: они должны разрушиться
раньше Host. Для остановки вызывайте `RequestStop()`. В графическом callback
оформляйте кадр через `Canvas::Begin()` и `End()`; при resize обновляйте Canvas,
а ввод переводите в ту же логическую систему координат, что используется для UI.

В ASCENT `Game::Events` и `Game::Tick` связывают ввод, симуляцию и отрисовку.
Правила игры остаются в `AscentGameplay`, поэтому тесты боя/прогрессии не требуют
создания окна. Проверяйте правила отдельно от presentation: воспроизводимый seed
и фиксированный шаг удобнее для регрессий, чем сравнение случайного ручного прогона.
Политики паузы, потери фокуса и накопления времени задаёт клиент; в ASCENT очистка
ввода также сбрасывает накопитель, чтобы после смены режима не выполнять старый ввод.

Аудио, привязанное к `Host::SetAudioTick`, должно жить дольше callback.
Перед уничтожением захваченного игрового объекта снимите callback через
`SetAudioTick({})`, как делает ASCENT. Для инструментов/benchmarks явно задавайте
нужную startup-политику через `ConfigureStartup(false)`.

## Ресурсы и сохранения

Ресурсный каталог и каталог пользовательских данных решают разные задачи.
ASCENT получает EXE-каталог через `Host::ExeDirectory()`, загружает `Locales`
рядом с EXE и содержит art/audio в Windows `.rc` ресурсах. При упаковке проверьте
внешние файлы локализации и необходимые runtime DLL; копии одного EXE может не хватить.
Используйте явные пути вместо зависимости от случайного рабочего каталога.

Для пользовательских данных есть `Host::UserDirectory(application)`.
`session::SaveProfilePayload(path, payload)` и `LoadProfilePayload(path)` работают
с сериализованным payload; формат, версия схемы, миграция и восстановление после
повреждения принадлежат игре. Не сериализуйте указатели и временные render handles.
Текущий `SaveProfilePayload` принимает непустой payload размером до 32768 байт;
ошибка передаётся исключением. Учитывайте этот предел при расширении профиля.
Проверяйте round trip и ошибочные входные данные, а не только факт появления файла.

У ASCENT `profile-scope.txt` рядом с EXE изолирует профиль копии: первая строка —
36 символов из строчных `0123456789abcdef-` (обычно GUID). Невалидная строка
возвращает обычный пользовательский каталог. Это соглашение ASCENT, не API Session.
Для smoke-прогонов используйте отдельный capture-каталог: игровые тесты не должны
перезаписывать обычные сохранения игрока.

## Проверять изменение в границах задачи

| Изменение | Минимальная полезная проверка |
| --- | --- |
| Правило боя, предметов, прогрессии | Детерминированный тест игрового состояния |
| Профиль/сериализация | Round trip, старый формат и повреждённый payload |
| Окно, ввод, Canvas | Запуск, resize, фокус, переключение режима, штатный выход |
| Аудио | Запуск/остановка и mute в затронутой сцене |
| SDK/линковка | Внешний MinimalGame через установленный package |

Для engine-регрессий выбирайте существующий CTest по имени через `ctest -R`.
Полный gate нужен для квалификации релиза; не запускайте его вместо каждого
узкого теста. Имена игровых команд вроде `--smoke-windowed`, `--capture-dir`,
`--enemy-test` принадлежат ASCENT и не являются CLI движка. Проверяйте их наличие
в версии клиента, которую запускаете; диагностические аргументы могут отсутствовать
в обычном EXE.

Compiler/CMake outputs храните в `build/`, локальные SDK, логи и захваты — в `.ai/`.
Готовую игровую копию можно держать в игнорируемом `LocalGame/`. Отчёты не подменяют
исходники и тесты и не должны попадать в коммит вместе с исправлением.
Для наблюдения готового EXE см. [[08 Auditor/Запуск Auditor]].
