# CTest и запуск тестов

Тесты регистрируются при `BUILD_TESTING=ON`; исполнение Windows-oriented бинарников требует рабочей Windows среды. Само наличие CTest target не доказывает, что тесты прошли на текущем дереве.

```powershell
ctest --test-dir build/full-debug -C Debug --output-on-failure --no-tests=error

# Список имен и label'ов текущего build tree
ctest --test-dir build/full-debug -C Debug -N

# Адресная регрессия Runtime
ctest --test-dir build/full-debug -C Debug -R EpidemicRuntime --output-on-failure --no-tests=error

# Не использовать -R для объявления полного acceptance
```

Для CMake target на отдельных уровнях: `cmake --build build/full-debug --config Debug --target EpidemicPublicHeaderSelfContainment --parallel`. Негативный architecture self-test вызывается `cmake -P cmake/ArchitectureFreezeSelfTest.cmake`.

Проектный скрипт `Invoke-Dev.ps1 -Action Full` выполняет clean полную матрицу данного профиля, архитектурную проверку, header self-containment, CTest, `Verify-Changed -Mode Deep` и `git diff --check`. Это гораздо более широкий gate, чем один локальный тест. См. [[09 Качество и статус/Матрица проверок]].

### Рекомендации для исправлений

Сначала воспроизведите точное падение, затем меняйте owner и запускайте адресные тесты. После cohesive изменений прогоняйте зависимые тесты, перед квалификацией по milestone повторяйте полную матрицу на зафиксированном дереве. Не путайте CI smoke с полной физической квалификацией Auditor.
