# Диагностика типичных проблем

### Неподдерживаемый generator

`Invoke-Dev.ps1` требует установленный Visual Studio generator `Visual Studio 18 2026`. При несовпадении генератора используйте новую build directory с установленным Visual Studio generator либо измените локальный workflow осознанно. Не правьте project policy только ради локальной среды.

### Ошибка запуска PowerShell скриптов

В рамках доверенной локальной копии используйте `pwsh -NoProfile -File ...` и проверьте `Get-ExecutionPolicy -List`. Изменение политики машинного уровня не требуется по умолчанию. Для скачанных `.ps1` может потребоваться `Unblock-File` после проверки источника.

### `CMakeCache.txt` с чужим compiler/config

Удалите только соответствующий `build/<profile>-<config>` после сохранения нужных артефактов. Повторная конфигурация в независимой папке лучше смешения профилей.

### Compile error из architecture freeze

Найдите прямую `#include`/link зависимость и сравните с [[02 Архитектура/Правила архитектурного freeze]]. Изменять allowlist без архитектурного решения недопустимо.

### `ctest` показывает ноль тестов

Проверьте `BUILD_TESTING`, путь к сконфигурированному каталогу, Debug/Release и выполненную сборку. Опция `--no-tests=error` предотвращает ложный успешный нулевой запуск.

### Auditor показывает UNKNOWN/INCOMPLETE

Это не доказательство исправности и не всегда ошибка агента. Нужно изучить Run evidence, capture provenance, поддерживаемый режим и границы наблюдения. [[08 Auditor/Понимание evidence]].

## Локализация проблем по границе ответственности

Если ошибка возникает до начала CTest, проверяйте CMake generator, compiler, SDK, architecture allowlist и link. Если CTest падает, проверяйте конкретный target и binary identity. Если Resource lease не освобождается, смотрите Support ownership и retry. Если Auditor рисует пустой граф, сначала проверьте raw capture completeness, затем symbol identity, а не исправляйте сам движок на основании отсутствующего evidence.
