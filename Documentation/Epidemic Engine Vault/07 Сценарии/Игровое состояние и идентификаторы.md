# Gameplay owners и Runtime идентичность

GameFramework размещает game-semantic state в именованных `GameplayWorldStateOwners`: Entities, ItemsInventory, Combat, Dialogue, World, SaveGame и других. Сервис-владелец принимает определённые команды и предоставляет queries. Конкретная интеграция двух владельцев относится к `IntegrationLayer`; `RuntimeBridge` является узким адаптером runtime-объектов.

`RuntimeObjectId` связывает records с Runtime, а не переносит fields NPC/предметов внутрь Runtime World/Scene. Нужно различать internal owner IDs и внешние runtime IDs. Их conversion и lifecycle следует сверять по публичным contracts (`ids.h`, `runtime_bridge.h`, `world.h`).

Новые runtime/gameplay вызовы оформляйте through ports, authorized adapters и state transactions. Цепочку для конкретной механики ищите по module public header и implementation, после чего покрывайте позитивными и негативными tests.
