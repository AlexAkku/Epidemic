# Подключение EngineBase и Runtime к приложению

Для 2D-клиента SDK 1.0.1 сначала рассмотрите
[[03 Работа с движком/Практическая интеграция игры|готовую композицию Presentation/Session]].
Ниже приведён низкоуровневый маршрут самостоятельной сборки сервисов; его
инициализация не добавляется поверх `presentation::Host`.

Пример для понимания последовательности берётся из `Documentation/EngineBase/using_enginebase.md` и `Documentation/EngineRuntime/using_engineruntime.md`. Здесь намеренно показаны **две независимые части**, объединение в Game зависит от выбранных frame handlers, production backends и lifecycle.

### Регистрация EngineBase

```cpp
#include <Epidemic/Core/application.h>
#include <Epidemic/EngineBase/engine_base_support.h>

int main()
{
    epidemic::core::Application app({ .application_name = "EpidemicGame" });
    epidemic::enginebase::RegisterEngineBase(app, {
        .runtime_name = "EpidemicGame",
        .log_module = "Game",
        .worker_count = 4,
        .memory_tracking_enabled = true,
    });
    app.Bootstrap();
    app.Initialize();
    return app.Run();
}
```

Это учебный фрагмент из репозитория, не шаблон полностью готового приложения. Варианты с окном, input, graphics и frame loops описаны в [[90 Первоисточники/Documentation/EngineBase/using_enginebase|исходном руководстве EngineBase]].

### Композиция Runtime

```cpp
using namespace epidemic::runtime;
EngineRuntimeOptions options{};
EngineRuntimeDependencies dependencies{};

auto prepared = PrepareEngineRuntime(options, dependencies);
if (!prepared) {
    return prepared.GetError();
}
auto committed = CommitPreparedRuntime(application, std::move(prepared.Value()));
if (!committed) {
    return committed.GetError();
}
EngineRuntimeServices runtime = std::move(committed.Value());
```

Это фрагмент, предполагающий существующий объект `application` и заполненные зависимости. Production profile требует соответствующие backends/commit target. Вызовы должны быть согласованы с моментом регистрации/инициализации. Их нельзя автоматически вклеить в `main()` без учёта lifecycle.

### Практический порядок

Создайте composition root, зарегистрируйте services, подготовьте Runtime aggregate, подключите FramePhaseHandler, используйте Runtime coordinator в игровых кадрах, остановите подсистемы в правильном порядке. Для production привяжите свои implementations к конкретным interfaces.

Сигнатуры: [[11 API/EngineRuntime/Support/runtime_support.h]]. [[02 Архитектура/Жизненный цикл]] · [[07 Сценарии/Runtime кадр]].

## Контрольный список запуска

1. Создайте `core::Application`; 2. зарегистрируйте EngineBase и необходимые runtime/frame services; 3. подготовьте `EngineRuntimeOptions` и `EngineRuntimeDependencies`; 4. выполните Prepare и Commit в Application; 5. `Bootstrap/Initialize`; 6. исполняйте `Tick` в нужной phase с корректным clock и budgets; 7. выполните `coordinator->Shutdown()` и обработайте retry; 8. завершите Application. Нельзя предполагать, что Runtime создан при одной лишь инициализации EngineBase.
