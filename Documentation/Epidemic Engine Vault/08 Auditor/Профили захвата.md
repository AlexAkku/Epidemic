# Профили и границы наблюдаемости

`Fast`, `Full`, `Deep` являются modes внешнего Auditor run. CMake `EP_AUDITOR_PROFILE` выбирает **иной аспект**: инструментированную физическую сборку. Эти две оси нельзя приравнивать.

### Capture mode

| Mode | Основное назначение |
| --- | --- |
| `Fast` | Локальные runs, CTest, stdout и метрики процессов |
| `Full` | Расширенные reports и source static scan |
| `Deep` | Дополнительно ETW/WPR и, если установлен, xperf post-processing |
| `Memory` | ASan и memory probes в отдельной `audit-memory` сборке |
| `Coverage` | Source coverage в отдельной `audit-coverage` сборке clang-cl |
| `Stress` | Запуск в профиле `audit-deep`; нагрузочный сценарий задаёт клиент |
| `Targeted Exact` | `audit-deep` с явно заданным target scope |

При Configure Auditor сопоставляет Fast/Full с `audit`, Deep/Stress/Targeted Exact
с `audit-deep`, Memory с `audit-memory`, Coverage с `audit-coverage`.
Start Game с фиксированным путём может наблюдать обычный EXE: режим не переписывает
его и не добавляет instrumentation. Практическая настройка и ограничения UI:
[[08 Auditor/Запуск Auditor]].

### Физический build profile

| `EP_AUDITOR_PROFILE` | Требования / особенности |
| --- | --- |
| пустой | Обычная engine сборка без Audit-only instrumentation |
| `audit` | MSVC x64 Windows, exact tracing |
| `audit-deep` | То же плюс shadow probes |
| `audit-memory` | MSVC x64 + AddressSanitizer + shadow allocation probes; отдельный runtime DLL |
| `audit-coverage` | clang-cl x64 Windows, source coverage |

Не собирайте разные физические профили в одной CMake build directory. `audit-memory` отключает несовместимые `/RTC` и incremental linking. Не считайте отсутствие verifier/ASan событий доказательством безопасности всей памяти: scope ограничен активными наблюдателями.

`Deep` mode не гарантирует наличие ETW raw trace без установленного WPR, прав, работоспособного broker и валидной capture. Всё недоступное должно оставаться `UNKNOWN/BLOCKED`, не `PASS`.

## Сопоставимость режимов

Fast/внешний sampling не предоставляет точный стек каждого C++ вызова. Audit instrumentation сообщает native call hooks в допустимом scope. Deep может подключать Windows WPR/ETW, если есть необходимые инструменты и права. Memory/audit-memory зависит от MSVC ASan и охвата allocation probes; её leak candidate не эквивалентен результату LeakSanitizer на Windows. Переключение профиля меняет наблюдаемость, поэтому сравнение без квалификации совместимости запрещено.
