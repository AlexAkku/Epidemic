# Владение состоянием и идентификаторы

`authoritative state` принадлежит конкретному owner. Derived/read-model может быть пересчитан, но не должен изменять чужой state обходным путём. В EngineRuntime `World` управляет логическим размещением/reality/residency, а `Scene` управляет hierarchy и пространственным представлением. Gameplay World и records EngineFramework добавляют смысл и используют IDs для связи.

Типичные границы:

* `ResourceHandle` служит для запроса состояния/содержимого; `ResourceLease` является основанием ownership, нужным для освобождения.
* `RuntimeObjectId` сопоставляет runtime-представление и gameplay record без переноса gameplay-полей вниз.
* Physics world transforms передаются через Support projection queue; публикация в Scene проходит отдельной phase.
* Simulation предлагает mutations через proposals/commit port, не пишет прямо в произвольные domain owners.
* Persistent data фиксируется через версии, snapshots, transactional границы и соответствующие owners.

Цель этих правил: не допускать двойного владения, повторного выполнения принятого префикса операций при retry и незамеченных partial commits. [[07 Сценарии/Игровое состояние и идентификаторы]] · [[07 Сценарии/Сохранения и детерминизм]].
