# Поддержка документации при изменении кода

Этот Vault является **снимком** конкретного архива и не отслеживает файлы на диске автоматически. Чтобы сохранить соответствие:

1. Зафиксируйте commit, uncommitted changes и дату получения исходников.
2. Выполните `cmake`/CTest и не переносите старые verdict на новый tree.
3. Замените исходную документацию в `90 Первоисточники/`, затем пересоберите каталоги публичных headers и module cards из нового кода.
4. Проверьте, что новые `[[wikilinks]]` разрешаются и `Mermaid` отражает CMake architecture graph.
5. Вручную проверьте страницы сценариев и статуса milestone после изменений контрактов.
6. Сохраните дату и SHA-256 исходного архива как provenance.

В папке `99 Служебное/` есть `manifest.json`, перечень прочитанных исходных документов и `check_vault.py`. Скрипт валидирует структуру `[[wikilinks]]`, но не заменяет сборку C++ или semantic review.

Смотреть [[09 Качество и статус/Текущее состояние и границы достоверности]].

## Воспроизводимость документации

Vault создан по zip-снимку, поэтому номера строк относятся к точному архиву, а не к любой последующей рабочей копии. При обновлении кода прежде всего сверяйте SHA-256 исходного архива и изменённые файлы. Для публичных API проверяйте сигнатуры, visibility и default values; для modules пересматривайте direct CMake links, test targets, error codes и contracts. Если новое поведение не покрыто тестом, оно должно оставаться описанным как неподтверждённое.

Служебный `check_vault.py` проверяет навигационные wikilinks и наличие файлов, но не делает семантическое сравнение с C++ кодом, не собирает проект и не выполняет Windows tests. После любого существенного рефакторинга требуется ручная сверка изменённых границ и автоматические проверки в исходном репозитории. «Актуальный» здесь означает «соответствующий снимку от 10.10.2026».
