# Workflow разработки и проверок

Исходный обязательный контракт для автоматизированной работы: `Development/AgentsRules/AGENT_RULES.md`. Его дополняют `WORKFLOW.ru.md`, `PIPELINE.md`, `Retrieval/README.md` и tools scripts. Полные файлы включены в [[90 Первоисточники/Development/AgentsRules/README|первоначальную документацию]] и не заменяются данной заметкой.

Рабочие правила: получить точный source context, определить область и graph зависимостей, написать наблюдаемое expected behavior, изменить только соответствующие owners, провести focused regression, проверить отсутствие regressions, сохранить реальные exit codes/reports. Длинные запуски могут выполняться изолированно в отдельных build directories, но разделение write ownership обязательно.

`Run-Quiet.ps1` запускает задания с memory budget и пишет stdout/stderr в `.ai/logs`. Для независимой проверяемости не превращайте nonzero exit в success и не ориентируйтесь на промежуточный tail вместо финального результата.

В рамках MS6 этапы acceptance и SRC mappings контролируются отдельным milestone input. Новый код Auditor не должен внедрять скрытые production probes в обычный Debug/Release.

## Когда изменение можно считать завершенным

Для завершения нужны: изменённый owner, контрактная спецификация, позитивный и негативный регрессионный тест, реальное выполнение relevant targets, проверка dependent boundaries и отсутствие unexpected mutation. При необходимости изолируйте параллельные CMake build directories; не запускайте в один mutable build tree одновременно несогласованные сборки. Сохраните результаты и ограничения независимо от размера изменения.
