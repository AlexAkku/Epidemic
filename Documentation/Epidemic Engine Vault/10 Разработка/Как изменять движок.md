# Как правильно изменить движок

Вначале определите authoritative owner и публичный контракт. Изменяйте минимальный набор C++ файлов, не вводя новую dependency edge до проверки архитектурных правил. Если требуется техническая связь Runtime majors, реализуйте port/adapter в `Runtime/Support`. Для игровых связей используйте Framework IntegrationLayer.

Порядок работы:

1. Через [[11 API/Индекс API]] найдите public header и module `CMakeLists.txt`.
2. Прочитайте [[02 Архитектура/Граница игрового кода]] и [[02 Архитектура/Правила архитектурного freeze]].
3. Найдите существующие tests и зафиксируйте ожидаемую семантику и негативные входы.
4. Измените owner и соответствующие реализации с минимумом переносов responsibility.
5. Добавьте/исправьте адресные unit и integration tests; убедитесь, что негативная проверка обнаруживает ошибку.
6. Соберите changed targets и адресные tests, затем нужную полную матрицу.
7. Обновите public docs и source-of-truth evidence, не подменяя `PARTIAL/UNKNOWN` на `PASS`.

Изменения не должны создавать вторичные authoritative caches, терять leases при failure или нарушать transaction boundaries. [[10 Разработка/Процесс изменения]] · [[09 Качество и статус/Матрица проверок]].
