## Подробное техническое описание (срез исходников)

В этом разделе сведения получены непосредственно из исходного C++ дерева и контрактной документации того же снимка. Наличие проверки в тестовом файле не означает, что она была выполнена при сборке Vault.

### Контракты и существенные инварианты

Ниже изложены конкретные формулировки исходного контракта модуля. Англоязычные фрагменты оставлены в исходной терминологии, чтобы не исказить условия атомарности, владения и восстановления.

#### Responsibility

Owns condition definitions and applied condition instances, stacking/materialization policy, periodic/expiration schedule links, per-subject indexes and condition change history.

#### Public headers and types

Public surface is rooted at `EngineFramework/GameplayWorldStateOwners/Conditions/include/Epidemic/GameFramework/Conditions/conditions.h`.

#### Dependency list

Direct production links are `EpidemicGameFrameworkFoundation` and `EpidemicFoundation`. No peer GameplayWorldStateOwner or Runtime module dependency is added by this delta.

#### External ports/callbacks/providers/backends

IConditionSubjectStateProvider is a non-owning read port used to validate subject state/materialization. Provider absence/failure does not become authoritative condition state.

#### Authoritative state

Frozen definition registry, instance vector, ID index, subject index, ID generator, revision, bounded journal and optional subject-state provider.

#### Derived/cache/index state

id_to_index_ and subject_index_ derive from instances_ and must agree after apply/remove/restore. Schedule link fields are part of instance state, not a second scheduler owner.

#### ID spaces, generations, revisions and cursors

ConditionInstanceId is generated by the service. Revision and ChangeCursor are checked. Snapshot includes ID generator and journal state so continuation does not reuse identity.

#### State machines

Definitions register before Freeze. Applied instances follow stacking rules, may pause/resume around materialization, receive periodic due callbacks and expire/remove for explicit reasons. Restore is rejected before Freeze because snapshot references current-build definitions.

Источник контрактов: `Documentation/EngineFramework/Conditions.md`; при расхождении фактического поведения с описанием необходима проверка тестов и реализации.
