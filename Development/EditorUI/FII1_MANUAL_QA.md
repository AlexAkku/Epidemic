# F-II.1 — ручная проверка Graph Canvas

Статус ручного прогона: **NOT RUN**. Computer Use при реализации не использовался.

Запуск: `Temp/U/distribution/EpidemicEditor/EpidemicEditor.exe` из корня репозитория. Развернуть окно. Создать отдельный тестовый проект и новый Graph через существующую команду New Graph. Открыть справа Graph Palette и Graph Node Inspector; снизу при необходимости Problems. Старый UI и отдельная установка IDEA не нужны.

## 1. Palette и Selection

Найти по поиску Input, Add и Control. В доступном каталоге должны быть Event, Native Call, Wait, Input, Output, Add, Multiply, Entry, Sequence, Branch, Repeat. Двойной клик или Add Node создаёт настоящий узел. Variables/Get/Set и C#/Entity недоступны с объяснением этапа; активные действия для них отсутствуют.

Кликнуть узел. Inspector должен показать его ID, тип, порты и поля. Переключиться между узлами и Graph-документами: Inspector следует native Selection. Идентификатор узла сохраняется при переименовании и перемещении.

## 2. Сквозной арифметический граф

Создать **Entry, два Input, Add, Output**. У первого Input задать Preview Input default = `7`, у второго = `6`, подтвердить Enter или Apply. Названия можно изменить на кириллицу. Соединить:

| Откуда | Куда |
|---|---|
| Entry / next | Output / in |
| Первый Input / value | Add / left |
| Второй Input / value | Add / right |
| Add / result | Output / value |

Нажать Compile: ожидается `OK compiled native VM`. Run Preview: `Completed`, в Graph References результат Output / value = `13`. Preview использует настоящий GraphInstance и GraphScheduler с отдельными native Time/Simulation services; это не запуск игрового мира.

Попытаться соединить Entry / next с Add / left, затем output с output, повторить существующую связь. Ожидается typed reject, неизменные связи и revision. Problems/строка ошибки должны показывать причину; Go to node или Go to Graph diagnostic node переводит к соответствующему узлу.

Подхватить существующую связь за входной порт, затем Escape: исходная связь остаётся. Перенести её на другой совместимый вход: одна транзакция и один Undo возвращают старую связь. Для удаления выбрать связанный узел → контекстное меню → Disconnect; Undo восстанавливает связь. Drop на пустое место не является неявным удалением.

## 3. Inspector, Save и неверный ввод

Изменить default Input на `9`, **не нажимая Apply**, затем Save/Ctrl+S: native commit должен завершиться до сохранения. Native Undo возвращает предыдущее значение; Redo возвращает новое.

Ввести `not-a-number` или `9223372036854775808`. Apply/Save должны дать ошибку, без изменения native значения или ложного успешного Save. Escape в поле отменяет draft. После исправления Save снова работает. Переключение Selection с draft не должно молча терять его: либо commit, либо явный отказ при invalid/stale значении.

Задать комментарий, Group, Bookmark и Breakpoint marker. Сохранить. Breakpoint — только маркер будущего F-II.4, он ещё не останавливает выполнение. Для Input/Event default относится к editor preview; реальные игровые inputs остаются в существующих scoped bindings.

## 4. Выделение и атомарный drag

Ctrl-click добавляет/исключает узлы. Shift-drag на пустом canvas выделяет прямоугольник. Ctrl+A выбирает до 64 узлов — это явный лимит одной UI операции. Клик по пустому canvas снимает выделение.

Переместить несколько выбранных узлов за один из них: взаимное расположение сохраняется. Один Ctrl+Z должен отменить весь drag, Ctrl+Y — вернуть его. Повторить на 50 узлах, если нужен расширенный прогон.

Начать drag, **удерживая кнопку мыши**, нажать Escape, затем отпустить. Все позиции должны вернуться, документ не должен получить edit. Следующий drag работает. Повторить с потерей фокуса/capture. Автоматически проверены JCEF input events для группы из 64 узлов; физическая мышь остаётся предметом этого ручного шага.

## 5. Copy/Paste, Duplicate и Delete

Выбрать два связанных узла → Ctrl+C. Навести мышь на новое место → Ctrl+V. Ожидаются новые Node/Port/Edge IDs, сохранённые внутренняя связь, настройки и относительные позиции. Внешние связи к невыбранным узлам не копируются. Clipboard принадлежит native workspace, это не обмен произвольным HTML/JSON через системный буфер.

Ctrl+D дублирует выделение. Delete удаляет выделенные узлы и incident edges. Один Undo восстанавливает всю операцию, включая метаданные. Copy/Paste/drag ограничены 64 узлами; общий бюджет native transaction — 256 команд. Слишком плотный или большой фрагмент должен отклоняться целиком.

## 6. Группы, комментарии и навигация

Выбрать несколько узлов → Group. У них появляется общая группа в подписи и Inspector. Через контекстное меню Select Group выделить её участников. Переместить/дублировать группу и проверить Undo. Комментарий виден в Inspector и tooltip узла; он сохраняется вместе с metadata.

Проверить pan, wheel zoom, Fit, Reset View и клик по миникарте. Save/Undo/редактирование имени не должны автоматически устраивать граф или сбрасывать камеру. Next Bookmark перемещает к отмеченному узлу. Контекстное меню должно создавать узлы в месте курсора.

## 7. Branch / Repeat / Wait через native scheduler

В отдельном Graph создать Entry, Branch, Repeat, Wait, Output и четыре Input со значениями `1`, `2`, `7`, `3`.

| Откуда | Куда |
|---|---|
| Entry / next | Branch / in |
| Input 1 / value | Branch / condition |
| Branch / true | Repeat / in |
| Input 2 / value | Repeat / count |
| Repeat / body | Wait / in |
| Input 7 / value | Wait / value |
| Input 3 / value | Wait / ticks |
| Repeat / done | Output / in |
| Wait / result | Output / value |

Compile → Run Preview. Ожидаются `Completed`, `game_ticks=6`, Output value = `7`. Wait подтверждает настоящий scheduler после продвижения отдельного native clock; UI не пропускает Wait вручную. Экстремальные графы завершают preview по ограниченному бюджету с соответствующим статусом.

Native Call — существующая зарегистрированная игровая операция. Её создание/сохранение поддержано; изолированный preview без gameplay owner явно отказывает с `ui.graph.native_preview_requires_play`. Реальные domain bindings/Play сохранены; произвольный фиктивный NativeCall не исполняется. Подключение authoring Graph к игровому scope относится к F-II.3.

## 8. Save/Open, окна и конфликты

Сохранить граф, закрыть вкладку, открыть снова. Имена, IDs, связи, координаты, defaults, комментарии, группы и маркеры должны сохраниться. Затем штатно завершить приложение и открыть тот же проект в новом процессе.

Вынести Graph через Open Tab in New Window. Проверить Selection, Inspector, Ctrl+S/Z/Y, закрытие отдельного окна и сохранность проекта в основном workspace. Если открыты две view одного документа, изменения приходят в обе; камеры независимы. Изменение документа из другой view во время drag должно отменять stale preview, не перезаписывая новую версию.

Find Uses показывает поддерживаемые Scene System → Graph ссылки. Для графа без таких назначений пустой список корректен; новый Graph↔Scene binding не реализуется в F-II.1.

## 9. Безопасный текст и лимиты

В имени/комментарии попробовать кириллицу, пробелы и `<img src=x onerror=alert(1)>`. Это должно отображаться текстом, без изображений, скриптов и сетевой загрузки. Порты сохраняют свои IDs.

Автоматически прогнаны native workloads 100/500/1024 и реальные JCEF projections 100/500, CSP/Bridge rejection, HTML injection и disposal/shutdown. Native лимит **1024** не повышался. Render графа из 2000 узлов не поддерживается: oversized snapshot/превышение native лимита отклоняется без изменения документа. Это не замер 2000-node render.

После прогона достаточно указать номера шагов и результат; для отказа — действие, ожидаемое/фактическое поведение и текст ошибки.
