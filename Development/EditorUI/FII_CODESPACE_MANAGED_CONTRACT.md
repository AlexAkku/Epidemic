# Code Space и managed lifecycle: контракт F-II.2

Решение F-II.0b, 2026-11-11. Это контракт реализации F-II.2; LSP, Rider и запуск пользовательского C# из Play ещё не подключены.

## Code Space

- Один настоящий Platform Editor/Document на канонический путь `.cs` внутри `Scripts` текущего проекта. Повторное открытие использует тот же `FileDocumentManager`, включая отдельные окна. Текст хранится в файле и Platform Document. Native `GraphDefinition` не содержит копии C# текста.
- Открытие проверяет containment после разрешения пути; переходы `..` и reparse/symlink за пределы проекта отклоняются. Bridge из Graph не имеет операций чтения, записи и запуска скриптов.
- Dirty, Undo/Redo и Save текста принадлежат Platform Document. Native-команды графов и сцены сохраняют свою историю. Активный редактор определяет Ctrl+Z/Ctrl+Y. Save All сначала завершает pending edits, затем сохраняет native-проект и изменённые текстовые документы; ошибки каждого владельца остаются видимыми.
- Внешнее изменение чистого файла обновляет VFS/Document. Изменение dirty-файла вызывает конфликт с выбором Reload / Keep / Compare. Сохранение проверяет fingerprint предыдущей версии и не затирает внешнее изменение молча. Закрытие dirty документа и проекта предлагает Save / Discard / Cancel.
- LSP: локальный `csharp-ls 0.28.0` и клиент LSP4IJ 0.19.3 — закреплённые кандидаты. Один сервер на корень проекта. Сообщения привязаны к поколению проекта, URI и версии Document; устаревшие diagnostics/edits отбрасываются, rename проходит WorkspaceEdit с проверкой путей и Undo. Отключение сервера сохраняет редактирование, Save и явный `dotnet build`; Problems содержит diagnostics, а не журнал успешных операций.
- Completion, hover, definition, references, rename, отмена запросов и восстановление после падения сервера проверяются отдельно. Проба initialize/hover не закрывает остальные проверки. SDK и restore контролируются проектом; открытие файла не запускает restore/build автоматически.
- Rider — необязательный внешний редактор. Discovery: явный путь пользователя, Toolbox, App Paths/установки, PATH. Запуск без shell, аргументы `--line`, `--column`, абсолютный путь передаются раздельно. Отсутствие Rider сохраняет встроенный редактор. Не используются private IDE APIs и плагины установленного Rider.

## Managed lifecycle

- C++23 остаётся владельцем сцены, Graph VM, времени, scheduler, ресурсов и результатов native-команд. Существующий opt-in C ABI v1, `ManagedHost`/`ManagedSession`, thread affinity, callback lease, Busy и запрет вызова закрытого handle сохраняются.
- Для будущего пользовательского C# принимается отдельный managed worker на поколение Play. Он размещает штатный hostfxr/ABI, а не вторую simulation. C++ передаёт вызовы и получает результаты на границе контролируемого tick. Worker не меняет native-проект напрямую.
- Поколение определяется проектом, hash сборки и счётчиком Play. Start публикует schema/handles только после успешной сборки и handshake. Ошибка сборки оставляет authoring доступным и не публикует частичную schema. Новая сборка после Stop получает новое поколение.
- Stop запрещает новые вызовы, завершает/отменяет текущие согласно timeout, отзывает handles/callback leases, закрывает сессию и завершает принадлежащий worker. Поздние ответы старого поколения отклоняются. Проверяемый факт выгрузки — завершение worker и освобождение блокировки DLL; collectible ALC не заявляется как существующая возможность текущего bridge.
- При падении worker или превышении timeout Play останавливается с диагностикой. Управление процессом ограничено PID/handle созданного worker. C++ only build продолжает работать без .NET. Новая межпроцессная оболочка не меняет ABI v1 без отдельной версии контракта.
- Автоматическая регистрация пользовательских типов и операций формирует проверяемое schema-описание с устойчивыми TypeId/PropertyId/OperationId. Порты Rete происходят из native schema; браузер не вводит собственный реестр типов. Несовместимое изменение schema сообщает ошибки ссылок, сохраняя исходный проект.

## Последовательность задач F-II.2

1. Настоящий Code Space на VFS/EditorFactory: один Document, фокус, клавиши, dirty, Save/Close, конфликт внешней записи.
2. Локальный LSP lifecycle и весь перечисленный набор запросов, diagnostics и отказоустойчивый fallback.
3. Rider discovery и безопасный file:line launch на доступной установке; отсутствие установки остаётся NOT RUN.
4. Явная сборка C# и schema export без выполнения пользовательского gameplay при открытии проекта.
5. Managed worker, versioned RPC, поколения и отзыв handles; native scheduler остаётся владельцем времени.
6. Turret V1 → Play/Invoke → Stop → пересборка V2 → новый Play; отказ старых handles, ошибки build/worker, отсутствие зависших процессов и DLL locks; C++ only регрессия.

F-II.0b не реализует эти пункты. Выбор отдельного worker является окончательным lifecycle-контрактом для F-II.2; его IPC и executable будут реализованы и квалифицированы в том этапе.
