# F-II.4 и F-II.5 — совместная ручная проверка

Сначала пройдите исходные пункты F-II.4 ниже, затем раздел Arena в конце. Кнопки меню находятся в `Epidemic`. Оба gate подтверждаются отдельно; предыдущие автоматические PASS не подменяют вашу проверку.

Статус: оба ручных gate ожидают вашего результата. Ниже полный прогон F-II.4 с десятью регрессиями, затем F-II.5. Для Arena используйте новый отдельный folder project; свои проекты сохраняйте отдельно. Работайте на копии проекта. Результат каждого пункта — PASS либо наблюдаемая ошибка. Запускайте EXE из ссылки в итоговом сообщении, разверните окно. Панели открываются через Epidemic → View (либо Find Panel). Сначала проверьте 10 сочетаний старого функционала.

Закройте прежний экземпляр редактора. Проверенная side-by-side сборка находится здесь (обычный Windows PowerShell, `pwsh` не нужен):

```powershell
& 'D:\MyProjects\Epidemic engine v2.0\Temp\U\verification-images\419e8cc7300843cc804647a91fd5296b\EpidemicEditor\EpidemicEditor.exe'
```

Старый `Temp/U/distribution` этим прогоном не обновлялся. Подробные автоматические результаты и ограничения: [FII5_REPORT](FII5_REPORT.md).

1. **Проект + Documents + кириллица.** Создайте проект `Регрессия F4`, папку `Content/Мои ассеты`, Scene и Graph с пробелами/кириллицей. Откройте оба документа, переименуйте Graph из Documents, Save, перезапустите через Recent Projects двойным щелчком. Имена, пути и документы сохраняются.
2. **Импорт + Sprite + Undo.** Импортируйте PNG с прозрачностью в вложенную папку; назначьте Prefab, поставьте его на Scene. Отмените/повторите размещение, сохраните. Sprite в Details и Scene корректен; успешный импорт отсутствует в Problems.
3. **Explorer + документы + dirty.** Откройте Prefab, Duplicate из Documents, Rename/Move копии, измените scalar поле. Закройте изменённый документ: Cancel оставляет его, Discard откатывает только его, Save сохраняет. Исходный Prefab не затронут.
4. **Prefab + overrides + две сцены.** Разместите один Prefab дважды, переопределите Health у первого, измените исходный Health Prefab. Первый сохраняет override, второй наследует новое значение; Revert Override у первого возвращает наследование. Поля не сжимаются.
5. **Graph + inline + clipboard.** Составьте Input→Add→Output; один операнд Add задайте inline. Измените его, Enter, Ctrl+C/V/X, Undo/Redo, Save/Open. Топология и значения сохраняются; Escape отменяет незафиксированный ввод.
6. **Graph + соединения + DnD.** Перетащите ноду из Palette; потяните связь, ПКМ→Add→категория→нода, завершите соединение. Подцепите существующую связь: Escape возвращает её, Delete удаляет, Undo восстанавливает. ПКМ-меню закрывается ЛКМ по пустому месту.
7. **C# + внешний редактор + компоненты.** Измените scalar default существующего пользовательского компонента в Code Space и VS Code, Build & Register. Непереопределённое поле обновляется, override сохраняется, Remove Component удаляет выбранный компонент. Ошибка сборки оставляет последнюю успешную generation доступной.
8. **Entity/Component references + дубликат.** В существующем Graph назначьте ссылку на второй placement/его компонент. Дублируйте первый placement, Save/Open, проверьте выбранную цель и validity. Удалите цель, Undo: отсутствующая/восстановленная ссылка определяется правильно. Это повтор регрессий прежних пунктов17/19/20.
9. **Несколько окон + selection + фокус.** Отделите Scene и Graph; переключайте Hierarchy/Explorer/Inspector, прокрутите Palette, меняйте selection. Splitters сохраняют размер, ID не засоряют подписи, Graph error overlay закрывается крестиком. Ctrl+Y — Redo, Ctrl+Delete — удаление строки в Code Space.
10. **Закрытие + восстановление.** В двух окнах измените разные документы, сохраните, закройте редактор, откройте проект в новом процессе. Layout, данные, ссылки, кириллица и native preview восстановлены; оконные кнопки находятся у края. Запустите/остановите существующий native Graph без C#.

## Подготовка сквозного сценария

11. Создайте Scene `Runtime Test`, Prefab `Target` и Graph `Damage Wait Damage`. У Prefab добавьте зарегистрированные компоненты `editor.example.health` (points=100) и `editor.example.movement` (speed=3, enabled=true). Это штатные компоненты из Inspector → Add Component, C# для данного сценария не нужен. Разместите Prefab на Scene в (0,0). По желанию назначьте заметный Sprite.
12. В Graph создайте Event, два Input, два Native Call и Wait. Input A=7, Input B=120. Соедините точно:

    - Event.next → Native Call 1.in;
    - Input A.value → Native Call 1.argument;
    - Native Call 1.next → Wait.in;
    - Native Call 1.result → Wait.value;
    - Input B.value → Wait.ticks;
    - Wait.next → Native Call 2.in;
    - Wait.result → Native Call 2.argument.

    Штатный Native Call данного профиля выполняет Damage над Health владельца. В Inspector Prefab выберите этот Graph как behavior. Save All. В Game Controls выберите `Runtime Test` как Play Scene. Откройте Game, Runtime Inspector, Debugger, Console, Problems и Profiler.

## F-II.4

13. **Непрерывный native Play.** Нажмите Play. Не используйте Refresh. Game показывает Target и Health=93, затем примерно через120 native ticks Health=86. Runtime Inspector показывает те же runtime points. Scene/Prefab authoring Health остаётся100. В Console/Debugger есть Started, Node, Waiting и Completed с session/tick; после завершения activationCount становится0.
14. **Pause и точный Tick.** Restart, быстро Pause до окончания Wait. Запишите Tick/Health/позицию; подождите3сек: они неизменны, интерфейс работает. Step Tick увеличивает Tick ровно на1 и остаётся Paused. Resume продолжает Wait с сохранённого native срока. Game 60/120 не меняет скорость ожидания: Runtime всегда60ticks/s.
15. **Breakpoint и Step to Node.** После Stop выберите Native Call 1; в Graph Inspector включите Breakpoint и Apply. Play останавливается перед Damage: Health100, Paused, подсвечена нода. В Debugger выберите activation, Step to Node выполняйте до первого Damage: Health93, игровой Tick при этих шагах не меняется. Это ограниченный переход к следующей ноде, а не Step Tick и не время Wait. Toggle Breakpoint выключает текущий runtime breakpoint; Continue продолжает. Stop из breakpoint завершается. После Stop снимите авторский Breakpoint и Apply.
16. **Wait и typed values.** Поставьте Pause во время Wait. В Debugger видны activation ID, текущая нода, instruction/native call counts, i64 значения портов, wake tick и remaining ticks. Step to Node не сокращает Wait; Step Tick сокращает его на1. Для Branch в отдельном прежнем Graph проверьте trace true/false и соответствующую ветку.
17. **Ввод и фокус.** В Play кликните Game, удерживайте WASD/стрелки: Target с Movement движется, Inspector World Position меняется. Клик/удержание ЛКМ направляет его к точке мира. Pause фиксирует позицию. Во время Pause задайте направление и нажмите Step Tick — ровно один шаг. Отпустите клавиши; Esc, уход фокуса и закрытие Game прекращают ввод. В Code Space ввод текста и редакторские shortcuts работают без управления игрой.
18. **Два окна — одна игра.** Отделите Game в Windows-окно; Scene, Graph и Debugger оставьте в другом. Сверьте session/tick в Game/Inspector/Graph badge; возможна задержка отображения до100мс, отдельной сессии не возникает. Поставьте Pause из любого окна — оба перестают продвигаться. Перенесите окно на другой монитор, верните; фокус и изображение сохраняются.
19. **Отображение.** В Game переключите Fit viewport и640×360/1280×720/1920×1080, при необходимости прокрутите. Пресеты задают размер Canvas в логических пикселях; физический размер при DPI виден в Profiler. Переключите Present60/120FPS. Это частота показа, а не частота Runtime; при недостаточной мощности реально измеренная FPS может быть ниже. Resize/сворачивание/разворачивание не меняют Health или скорость игры.
20. **Restart/Stop и readonly.** Restart создаёт новый session ID и берёт Health100 из authoring; Graph повторяет93/86. Runtime Inspector не позволяет редактировать значения. Попытка authoring-write при Play запрещена. Stop очищает живые runtime entities и Game; авторское Health100 и сохранённый Graph не изменились. Повторный Stop безопасен. Save, закройте и откройте проект другим процессом: игра не запускается сама, Health100.
21. **Trace/Console/Problems.** После двух Play-сессий откройте Console → Filters: поиск, severity, Current session only, Graph, Entity, Activation, Tick. История старой сессии помечена отдельно. Copy копирует строки. Двойной щелчок/Go to Source открывает адресуемую Graph-ноду/C#file:line/asset; Go to Entity выбирает placement. В Problems отсутствуют Info/успешные сообщения; ошибки содержат источник, когда он предоставлен native/managed диагностикой.
22. **Ошибка выполнения.** После Stop измените Input A на1000, Play. Недопустимый Damage переводит сессию в Failed; в Problems есть native ошибка и привязка к ноде, редактор остаётся доступен. Stop безопасен, authoring Health100. Верните Input A=7. Для ранее проверенного C# Graph вызовите тестовое исключение: диагностика сохраняется, Stop/Restart доступны, переход к C# открыт при наличии source location.
23. **Отмена и несколько активаций.** Разместите Target дважды, Play: отдельные activation IDs и независимые Health. Pause→Stop во время Wait: Canceled/Stopping/Stopped, ни один Damage не выполняется после Stop. Ссылки на удалённую ранее Entity показывают Missing, а не другой живой объект. Авторские удаления во время Play остаются запрещены.
24. **Profiler.** Проверьте source/unit у tick p50/p95, FPS/frame p50/p95 каждого видимого HWND, native/UI working set, entities/activations, preview residency, import/build busy. Backend CPU total — cumulative ms, не процент; Dropped catch-up ticks показывает нативный перегрузочный backlog. GPU duration, allocations и per-renderer JCEF RAM при отсутствующем provider честно показывают Unavailable. Источники: существующий Diagnostics/Auditor SPI и native Renderer/process/resource diagnostics. Счётчики не являются второй симуляцией.
25. **Закрытие и повтор.** Закройте/откройте отделённый Game несколько раз, затем закройте проект во время Pause и откройте заново. Нет зависшей сессии/картинки/ввода, orphan HWND и сообщений stale handles. Автоматическая проверка100циклов дополняет, но не заменяет этот визуальный повтор. При корректной работе подтвердите F-II.4-GATE и приемлемость измеренных бюджетов из отчёта.

## F-II.5 — Arena: сначала полностью native профиль

1. **Подготовка.** Stop, создайте новый folder project `Арена F5`. Выберите `Epidemic → Project → Create F-II Arena Sample`. Дождитесь импорта. В Documents должны появиться `FII Arena`, четыре Prefab и `Arena Wave Graph`; в Content/FII_Arena — Turret.png, Enemy.png и Projectile.png; в Code Space — Scripts/ArenaManagedTurret.cs. Выберите FII Arena в Game Controls, Save All. Повторное создание не должно перезаписывать имеющиеся документы/файлы.
2. **Что в sample.** Player/Turret — один синий управляемый Entity; красные Enemy движутся влево; жёлтые Projectile направляются к цели. Отдельный spawn point находится справа. В Inspector Prefab доступны Health (points/maximum), Movement и gameplay.* компоненты. У турели range=6, cooldown=15ticks, damage=10. Enemy имеет30HP, один hit наносит10. WaveSpawner создаёт две волны по3 Enemy с интервалом30ticks. Дополнительные3 Enemy создаёт Graph через Repeat/Spawn/Wait. Это две разные наблюдаемые причины Spawn, а не повторный игровой цикл.
3. **Native Play.** Play без Build & Register C#. Проверьте движение Enemy, появление волн, наведение Projectile, попадания, уменьшение HP и исчезновение убитых Enemy/Projectile. В Runtime Inspector у Player растёт gameplay.state.currency при убийствах; у spawn point растёт wave. В Console/Debugger видны Spawned, ProjectileHit, Damaged, Died, WaveCompleted. Уничтоженная цель не получает повторные попадания.
4. **Ввод и его сброс.** Щёлкните Game, двигайте Player WASD. Щёлкните другой редактор: движение прекращается, текстовые shortcuts редактора работают. Повторите с Escape, Alt+Tab, Pause/Resume и закрытием отделённого Game. После возврата Player не должен двигаться до нового нажатия. Стрелки являются fallback при отсутствии gameplay.inputbindings; в sample стоят явные WASD bindings.
5. **Сохраняемые bindings.** Stop. У Player Prefab в gameplay.inputbindings смените right с68(D) на76(L), left с65(A) на74(J), Save All. После Play действуют J/L, а A/D больше не двигают Player. После Save/Close и нового процесса настройки остаются. Верните65/68 для последующих пунктов. Значения — Windows virtual key codes; Ctrl/Alt/Meta и Escape не назначайте.
6. **Один clock.** Во время волны Pause: Enemy, Projectile и сроки Wait не меняются, UI остаётся доступен. Step Tick продвигает ровно один tick; Repeat/Wait продолжаются по этому же tick. Выберите Time0.5x/2x и Resume: скорость игры меняется, presentation60/120 не меняет скорость симуляции. Restart начинает исходную арену, HP/валюту/волну; Stop останавливает её полностью.
7. **Graph и typed reference.** Откройте Arena Wave Graph: Event → Branch → Repeat → Spawn → Wait. Branch получает validity настоящей ссылки на первоначального Enemy placement. Через существующий Scene↔Graph DnD выберите другую цель ссылки, Save. Включите breakpoint у Spawn; Play/Pause, Step to Node и Continue должны вести себя как в F-II.4. Step to Node не двигает время Wait. После Stop снимите breakpoint. Если исходный Enemy отсутствует при старте, Branch не запускает Graph-спавн; WaveSpawner остаётся отдельным компонентом.
8. **Параметры физики.** Stop, измените Enemy Collider shape:0=AABB,1=Circle; radius/half_x/half_y задают мировые extents с учётом абсолютного scale. Проверьте обе формы. При mask=0 контактов и damage нет; верните Enemy layer2/mask5. Projectile layer4/mask2/trigger=true. Trigger даёт события без физического отталкивания; снаряд обрабатывает trigger как попадание. Полная Rigidbody dynamics не заявлена; AABB остаётся выровненным по мировым осям при вращении визуала.
9. **Lifecycle и границы.** В начале волны Stop, затем Restart несколько раз; закройте проект во время активной волны. Не должно быть продолжающихся spawn, движения, orphan окон/процессов или старого input в другом проекте. После Stop авторские Enemy points=30 и Player points=100, currency=0. Lifetime очищает промахнувшийся Projectile; невозможная скорость/NaN/Inf/недоступный Prefab должны отвергаться с диагностикой, без повреждения проекта.
10. **Два окна.** Отделите Game и Graph/Debugger в независимые Windows-окна. Обе панели показывают одну session/tick, Pause/Step/Stop из любого доступного controls согласованы. Перенос между мониторами не ускоряет игру. Закройте отдельное окно, откройте Game снова; авторские данные и session не дублируются.

## F-II.5 — подключение C# к тому же gameplay owner

11. **Сборка.** Stop, откройте Scripts/ArenaManagedTurret.cs в Code Space, прочитайте DamageSelf. Он настраивает native Turret Range/Cooldown/Damage, затем вызывает Gameplay.ApplyDamage и Award. Нажмите Build & Register C#. Операция ArenaManagedTurret.DamageSelf должна появиться в Palette/C#; ошибки — в Problems с переходом к исходнику. Внешний Rider необязателен, VS Code подходит для проверки синхронизации файлов.
12. **Компонент и Graph.** Откройте Arena Player Turret Prefab, выберите корневой Entity, Add Component → arena.ManagedTurret. Создайте новый Graph `Managed Arena`, добавьте Event, Input со значением0 и ArenaManagedTurret.DamageSelf; соедините Event.next → DamageSelf.in и Input.value → DamageSelf.argument. У component arena.ManagedTurret выберите этот Graph как behavior (не удаляйте исходный behavior корневого Entity). Save All. Если предлагается запуск устаревшей generation, сначала завершите Build & Register актуального исходника.
13. **Общая Health, а не её копия.** Play: Runtime Inspector у Player показывает native editor.example.health.points=93 и увеличившуюся gameplay.state.currency. C# не должен менять только собственное одноимённое поле. Редакторский Prefab points остаётся100. В sample C# нет собственного clock/timer/health implementation: ApplyDamage исполняется в C++ с текущим Entity scope.
14. **Изменение параметров.** Stop, измените Damage с7 на14 в непереопределённом C# default, Build & Register, Save, Play: native HP=86; новые снаряды наносят14. Измените Range/FireRate и убедитесь, что они настраивают настоящую турель после старта managed Graph. Для проверки смерти поменяйте Damage на100: событие Died должно быть однократным. Затем верните7. Неподдержанный отрицательный amount/невалидная конфигурация должны давать ошибку, не crash; Stop из Failed безопасен.
15. **Различайте authoring/runtime.** Поля в Runtime Inspector read-only. После Stop Player.points снова100, runtime currency не записана в authoring. Не используйте Editor Save как savegame: для F-II.5 прогресс хранится только в текущей сессии. Обычные Save/Undo/Redo редактируют документы, а не игровой прогресс.
16. **Новый процесс и повтор.** Save All, закройте редактор полностью, запустите свежий EXE и откройте проект через Recent Projects. Prefab/Graph references, PNG, bindings, C# исходник/schema и component должны сохраниться. Play снова даёт93HP и ту же игру. Выполните Pause/Step, Stop. На отдельном чистом native sample повторите Play без регистрации C#: native профиль обязан работать.
