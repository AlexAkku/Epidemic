## Уточнение пунктов 14–21 после ответа владельца

Пункты 1–13 приняты владельцем 2026-11-16. Для продолжения остановить Play. Использовать Scene с двумя placements одного Prefab, назвать их A/B и разнести в viewport. Не менять Prefab между сравнениями identity. Начинать каждый новый scope-тест с отдельного Graph, чтобы старые ссылки не влияли на результат.

**14. Из входа Graph к объекту.** Добавить Is Entity Valid. Его круглый левый порт reference — вход ссылки, правый valid — числовой результат. Зажать Alt, затем ЛКМ именно на круглом reference; удерживая, перенести указатель на строку A в Scene Hierarchy. Дождаться проверки цели (Checking reference target… → Reference target · release to link), отпустить ЛКМ, затем Alt. Если появился Create Graph Reference, выбрать Reference Entity. Возле Graph появятся reference-node и провод к reference; новый объект в Scene не появляется. Один Undo удаляет узел и провод вместе, Redo возвращает. Для B добавить второй Is Entity Valid с пустым reference и повторить перенос к видимому B во viewport. Не использовать занятый вход для положительного теста.

**15. Из объекта к Graph.** В Hierarchy сначала обычным кликом выбрать A. Зажать Alt до нажатия ЛКМ, потянуть строку A в пустое место Graph, отпустить. В Create Graph Reference выбрать Reference Entity. Появится только reference-node без провода: конечный вход не был указан. Повторить с B; сравнить строки identity в Node Inspector: placement различается, prefab и entity для той же корневой сущности совпадают. Затем добавить новый Is Entity Valid и потянуть A непосредственно на его reference — теперь создаются узел и провод. Повторить начало переноса из viewport: Alt+ЛКМ на самом видимом объекте. Reference Prefab Instance означает конкретное размещение, Reference Prefab Definition — общий ресурс Prefab; Definition не должна различаться у A/B. Для сравнения Entity выбирать одинаковый вариант и одну и ту же сущность, а не дочерний узел.

**16. Тип Component и запреты.** Добавить проверку Is <тип> Valid для реально имеющегося компонента Prefab, например Health. Из её пустого reference выполнить перенос к A. В выборе должен быть подходящий Get <canonical type> / Get Component; после создания Node Inspector reference-node показывает component и part. Проверить запреты отдельно: (a) существующий Health-reference соединить с reference проверки другого компонента; (b) его output соединить с числовым входом Add или control/event-входом; (c) Alt-перенос A бросить на уже занятый reference. Новая связь/узел при отказе не остаются, прежняя связь сохраняется, сообщение об отказе допустимо. Если второго типа проверки нет, отметить только этот подпункт NOT RUN и назвать доступные типы. Запрет несовместимого провода и запрет занятого входа — разные проверки.

**17. Навигация и устойчивость identity.** Выбрать созданный reference-node (не Is Valid), открыть Node Inspector. Записать его node ID и строку reference identity. Jump to Reference Target должен выделить именно A; если Scene не видна, открыть её и посмотреть выделение. Find Target References должен показать имена Graph и node=… в текстовом отчёте Graph/Node Inspector; отдельное окно результатов не требуется. Переименовать A, затем переподчинить его подходящему родителю в той же Scene: ссылка жива, ID reference-node прежний. Удалить A: узел остаётся и получает Missing Reference. Один Undo возвращает A, статус Missing исчезает, identity и провод сохраняются.

**18. Исполнение ссылки.** В отдельном Graph добавить Entry, Output, Is Entity Valid и ссылку на живой A. Соединить Entry.next→Output.in, Reference.output→Is Entity Valid.reference, Is Entity Valid.valid→Output.value. Compile, затем Run Preview: результат 1. Удалить A в Scene и повторить: 0, а не удаление reference-node или ошибка приведения reference к числу. Вернуть фокус Scene и Undo удаления, повторить Preview: 1. Открытый Prefab-ресурс без размещения не заменяет выбранный A. Использовать Entity-reference для этого теста, не Prefab Definition.

**19. Разные области ссылок.** (a) В новом Graph перетащить A в пустое место и выбрать Reference Prefab Definition. Создать такую же ссылку от B: обе указывают на один ресурс; удаление только A не делает Definition отсутствующей, пока Prefab существует. (b) В другом чистом Graph открыть Prefab Hierarchy и перетащить корневую/дочернюю сущность Prefab, выбрав Reference Entity. В identity document относится к Prefab, placement=0. Это ссылка внутри определения, не на A. (c) В третьем Graph создать Entity-reference на A из Scene S1. Создать вторую Scene S2 с размещением и попытаться добавить от него Entity-reference в этот же Graph: должно быть отклонение scope, прежняя ссылка S1 сохраняется. Выбор Prefab Definition для отрицательного теста не подходит: общие определения разрешены независимо от Scene.

**20. Отмена и закрытие.** Посчитать узлы/связи. Начать допустимый Alt-перенос, дождаться preview, нажать Escape и отпустить мышь: изменений и подсветки не остаётся. Повторить, отпустив над пустым участком верхней панели вне области назначения: тот же результат. После каждой отмены выполнить обычный допустимый перенос — он работает и отменяется одним Undo. Если во время Windows drag доступно закрытие source/target вкладки или отдельного окна с клавиатуры, проверить отсутствие частичных edits и работоспособность следующего переноса после открытия. Если ОС перехватывает клавиши и закрытие не происходит, этот подпункт NOT RUN, а не FAIL. Смена проекта и backend reconnect проверены автоматическими тестами; специально завершать процессы для этой ручной приёмки не требуется, их не отмечать как выполненные вручную.

**21. Независимые окна и DPI.** Вынести центральную вкладку Graph в отдельное окно Windows, Scene оставить в главном. Повторить 14 и 15 в обоих направлениях между окнами. Перенести отдельное окно на второй монитор и повторить; затем повторить при масштабе Windows 150% (если 100% уже пройден), по возможности на мониторах с разным масштабом. Масштаб Windows не равен zoom графа. Для каждого прохода наводить точно на reference и на A/B: нет смещения попадания, случайного выбора соседа или пропуска drop; после операции кликнуть узел Graph и проверить Delete/Undo, затем выделение в Hierarchy. При необходимости после смены DPI штатно перезапустить Editor и заново разнести окна. Невыполненные конфигурации указать NOT RUN; наличие второго HWND само по себе не заменяет перенос мышью.
