# Числа в Graph: i64 и f64

Отправная точка текущего изменения:c02355b; повторная приёмка владельца20 ноября2026. Операции и время исполняет существующий C++ Graph VM/Runtime Scheduler. Java/JCEF отображают данные и отправляют команды.

В Palette и Add menu показан один Input/Output в Data и один элемент каждой Math-операции. Native-каталог сохраняет прежние TypeId для совместимости; это не отдельные пункты палетки. Новые узлы начинают в Auto. Целый литерал выбирает i64, десятичная точка/экспонента — конечный IEEE754 double (f64). Соединённые Auto-узлы согласуют тип в C++: дробный авторский литерал или фиксированный f64 требуют f64 для числового компонента связности; после удаления такого требования он возвращается к i64. Неактивные, подключённые вместо литерала поля сохраняют свой авторский тип.

Замок на узле и в Graph Inspector выбирает Auto / Lock i64 / Lock f64. Фиксированный тип не меняется из-за соседнего узла. Auto может согласоваться с ним; конфликт двух фиксированных типов, дробного значения и i64 или потеря точности отклоняют всю транзакцию. Это не скрытое обрезание числа. Для намеренного преобразования остаются Convert i64 to f64 / Convert f64 to i64; последнее отбрасывает дробную часть с проверкой диапазона. Native/managed call ABI остаётся i64→i64 и является ограничением типа, как прочие порты вне Auto-family. Математика и исполнение остаются в существующей VM.

Каталог `kNumericRecipes` в Runtime/Graph — единый источник новых TypeId, названий и операций. Game Schema регистрирует его, native catalogue проецирует в Palette/Rete. Java не содержит математической реализации или альтернативного каталога.

Добавлены Subtract, Divide и Integer Divide в обоих типах. Деление i64 отбрасывает дробную часть; Divide f64 сохраняет её. Integer Divide f64 возвращает целую часть частного в f64. Round Up/Down дают ceil/floor. Отдельный Round (0.6 up, f64) реализует именно порог, указанный владельцем:1.5→1,1.6→2,−1.6→−2; это явно подписанный режим, а не стандартный порог0.5.

На wire и в существующих default/settings сохраняются точные64 bits; тип задаётся PortDefinition.type_id. f64 кодируется bit_cast, а не числовым приведением к i64. Разбор текста, вычисления и проверки диапазона происходят в C++; UI форматирует полученное число. Формат GraphDefinition/DTO v5 и IPC envelope v4 не меняется. Новые значения Operation добавлены в конец enum; существующие значения и TypeId сохраняются. Instruction.value_type относится только к process-local IR. GraphDefinition codec не меняется. Версия graph_authoring повышена с1 до2: numeric_mode=Auto/i64/f64 и два бита исходных типов литералов numeric_seed. При чтении v1 режим Auto; sentinel255 разрешает восстановить исходные признаки из старого TypeId/портов, сохраняя старые f64 значения. Версии выше2 отвергаются. DTO marker byte использует свободные биты2–3 для режима и4–5 для seed; bookmark/breakpoint сохраняют биты0–1.

Inline literals, Input defaults, native Undo/Redo и Save/Open используют действующие команды/сериализацию. Оба пути VM — data и control flow — проверяют типы. NaN/Inf, деление на ноль и переполнение отклоняются; signed division MIN/−1 не вызывает UB. Отчёт Preview и runtime port values форматируются без обнуления малых дробей через to_chars.

Проверки и текущий gate: [исправления регрессии](FII45_REVIEW_FIXES.md). [Ручной прогон](FII45_REVIEW_QA.md).

Согласование типа, правка значения и подключение сохраняются одним EditorWorkspace::Execute и одной записью Undo/Redo. Numeric authoring adapter строит временный кандидат GraphDefinition для планирования; авторитетные граф, проверка, история и сохранение принадлежат существующему EditorProject. Java/JS форматируют native DTO и посылают команды, не вычисляют игровую арифметику.
